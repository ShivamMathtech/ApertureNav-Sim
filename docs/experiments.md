# Experiments and interpretation

Run `python -m aperturenav.cli --benchmark`. Six opening widths are tested with
a fixed seed. The default vehicle envelope is 0.36 × 0.36 × 0.16 m, per-side
margin 0.10 m and position uncertainty 0.01 m.

Each run has `config.yaml`, `summary.json`, `telemetry.csv` and `events.csv`.
The CSV contains position, velocity, yaw, mission state, remaining clearance,
distance and collision count. JSON reports success, duration, path length,
peak speed, near-frame clearance and sample count. `benchmark.json` links all
runs and reports the successful traversal fraction for that exact case set.

Some widths deliberately fail the fit test. A correct abort is a safety-test
pass but a traversal failure. These counts should be reported separately.
Local simulation directly observes configured geometry; it does not measure
camera detection accuracy, localization error or perception FPS. Those metrics
are intentionally absent, rather than filled with synthetic performance data.

For ROS recordings, optionally run:

```bash
ros2 bag record /clock /drone/odom /drone/camera/image_raw /drone/depth/image_raw /aperture/pose /mission/state /drone/cmd_vel /sim/telemetry
```

Stop recording with Ctrl+C. The command writes genuine ROS messages. The web
Experiments tab reads the JSON summaries generated by the running installation.
